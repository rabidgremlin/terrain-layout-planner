# Domain docs

This repo uses a single context:

- `GLOSSARY.md` at the root contains domain terminology.
- `docs/adr/` contains architectural decisions.

Before exploring the codebase, read the glossary and ADRs
relevant to the work. If they are absent, proceed silently;
domain-modeling creates them when needed.

Use glossary terms in code, tests, issues, and proposals.
Flag conflicts with existing ADRs explicitly.

Use domain-modeling to resolve terminology gaps and record
qualifying architectural decisions.
